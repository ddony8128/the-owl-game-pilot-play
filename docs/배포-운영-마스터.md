# 부엉이게임 파일럿 — 배포 · 운영 마스터 (마피아 / 디펜스)

이 문서는 이번에 분리한 **마피아(2게임)**와 **디펜스(3게임)**를 **독립적으로 운영**하기 위한 배포·운영 체크리스트입니다.
(이상교통은 기존 배포로 이미 운영 중 — 여기서는 다루지 않습니다.)

> 두 게임은 명단(`players`)·게임상태(`game_state`)가 전역 공유 구조라 **각자 별도 Supabase + 별도 Vercel** 로 분리합니다.

## 2. Supabase (게임당 1개)

> ⚠️ 이 레포에는 스키마 파일이 없습니다(스키마는 기존 운영 프로젝트에만 존재). 새 프로젝트는 **기존 DB를 통째로 복제**해 만듭니다.

절차 요약 (상세: **`docs/운영-supabase-분리-가이드.md`**):
1. 기존(이상교통) Supabase 를 `pg_dump` 로 **스키마+데이터 전체 덤프**.
2. 새 프로젝트(`owl-mafia`, `owl-defense`) 생성 후 덤프 적용.
3. **`docs/sql/game-archive.sql`** 적용 (마피아/디펜스 플레이 데이터 보존 테이블).
4. 새 프로젝트 대시보드에서 **"전체 초기화(참가자 포함)"** 1회 → 복제돼 온 데이터 정리.

### 전체 초기화 (다음 팀 준비)
- **권장**: GM 메인 대시보드 → **참가자 관리 → "세션 종료 / 다음 팀 준비"** 버튼.
  (직전 판 자동 아카이브 + 주가/페이즈/몬스터 시드까지 정확히 재설정 — 앱이 처리)
- **보조(SQL)**: `docs/sql/전체초기화.sql` (런타임·명단만 비움). 실행 후 **반드시 대시보드 "진행 상태만 초기화"를 한 번 더 눌러 시드를 복원**할 것.

## 3. Vercel (게임당 1개)

각 게임 프로젝트마다:
1. 이 레포를 Vercel 에 연결, **배포 브랜치를 해당 게임 브랜치로 지정**(`2game-only`=마피아, `3game-only`=디펜스).
2. 환경변수:

   | 변수 | 값 |
   | --- | --- |
   | `SUPABASE_URL` | 해당 게임 Supabase Project URL |
   | `SUPABASE_SERVICE_KEY` | 해당 게임 Supabase service_role 키 |

3. 배포 후 URL 을 §1 표에 기입.

> 브랜치 오연결 주의: **마피아=`2game-only`, 디펜스=`3game-only`**.
