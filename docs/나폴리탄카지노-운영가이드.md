# 나폴리탄 카지노 — 8번출구 GM 운영 가이드

이 문서는 **나폴리탄 카지노** 세션에서 *이상교통 8번출구* 파트를 운영하는 GM을 위한 매뉴얼입니다.
8번출구 담당자가 아닌 다른 GM도 이 문서만 보고 진행할 수 있도록 작성되었습니다.

> 핵심 한 줄: **8번출구 대시보드 = 나폴리탄 카지노 세션의 참가자 목록 기준점.**
> 여기서 참가자를 등록/초기화하면 Rule Slot 등 같은 DB를 공유하는 다른 파트도 그 목록을 따른다.

## 2. 시작 전 세팅

1. **참가자 등록** — `/dashboard/x9a2k7/main` → "나폴리탄 카지노 참가자 관리"에서
   이번 세션 참가자의 닉네임을 모두 등록한다. (총 N명 표시 확인)
2. **닉네임 안내** — 등록한 닉네임을 참가자에게 그대로 알려준다.
   참가자는 `/` 진입 후 **딜러가 등록한 닉네임을 그대로** 입력해야 입장된다.
   (등록되지 않은 닉네임은 입장 불가)
3. **기기 준비** — 대시보드 기기, 참가자 플레이 기기, Rule Slot 기기, 블루투스 스피커 연결.
4. **활성 게임 확인** — 메인 대시보드의 게임 상태가 `subway`인지 확인.
   (`subway`가 아니면 참가자 화면이 잠금 상태가 된다.)

---

## 3. 8번출구 운영

- **제한 시간은 35분입니다.** (타이머/안내문/판정 모두 35분 기준으로 통일됨)
- 참가자는 입장 직후 **비활성(대기) 상태**로 시작한다. GM이 타이머를 시작해야 이동 버튼이 활성화된다.
- **타이머 조작**: `/dashboard/x9a2k7/subway` 의 카운트다운 영역에서 `시작 / 일시정지 / 리셋`.
  - `시작` — 35분 카운트다운 시작(참가자 이동 가능).
  - `일시정지` — 경과 시간 유지한 채 멈춤.
  - `리셋` — 35분 대기 상태로 되돌림.
- **진행 모니터링**: 같은 화면에서 참가자별 현재 출구 번호, 위치, 리셋 횟수, 완료 여부를 확인.
- **탈출 성공/실패 확인**:
  - 성공 — 8번 출구 도달 시 참가자 화면이 자동으로 결과 화면으로 전환, 대시보드에 완료 순위/소요시간 표시.
  - 실패 — 35분이 지나면 미완료 참가자는 자동으로 실패 처리된다.

## 4. 세션 종료 / 다음 팀 준비

`/dashboard/x9a2k7/main` → "나폴리탄 카지노 참가자 관리" 하단의 **세션 종료 / 다음 팀 준비** 영역.

- **진행 상태만 초기화 (참가자 유지)** — 같은 참가자로 8번출구만 다시 시작할 때.
- **세션 종료 / 다음 팀 준비 (참가자 포함 초기화)** — 다음 팀을 받기 전.
  - 참가자 목록 + 8번출구 진행 상태가 모두 비워진다.
  - 참가자 목록이 비면 **Rule Slot 랭킹도 자동으로 비워진다**(아래 §5 참고).
  - 종료 직전 이번 세션의 8번출구 플레이 지표는 영구 보존 테이블에 자동 적재된다.

> 세션 종료 후 Rule Slot 랭킹이 실제로 비었는지 한 번 확인하고 다음 팀을 받는다.

## 5. Rule Slot 연동 (DB 공유 규약)

Rule Slot은 **별도 프로젝트**이며, 이 프로젝트와 **같은 Supabase DB를 공유**한다.
이 저장소가 보장하는 연동 규약은 다음과 같다.

- **참가자 목록의 기준 = `players` 테이블** (`id` uuid, `nickname`).
  - 8번출구 대시보드의 참가자 등록/제거가 곧 이 테이블의 행 추가/삭제다.
  - Rule Slot은 이 `players` 테이블을 직접 읽어 "등록된 닉네임만 플레이 가능"을 판정한다.
- **세션 종료(전체 초기화) 시 `players` 행이 전부 삭제**된다.
  - Rule Slot은 "현재 `players`에 남아 있는 닉네임의 기록만" 랭킹에 표시하면,
    세션 종료와 동시에 랭킹이 자동으로 비워진다. (Rule Slot 기록 테이블을 따로 지울 필요 없음)
- Rule Slot의 점수/종료시각/패널티 기록 테이블은 이 저장소의 초기화 대상이 **아니다**(보존됨).
  랭킹 노출 여부는 위의 `players` 필터로만 제어된다.

> 따라서 이 저장소에서는 Rule Slot용 별도 API/CORS가 필요 없다. 규약은 `players` 테이블 하나다.
